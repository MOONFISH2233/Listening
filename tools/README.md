# tools — 可复用的工具

与 `spike-asr/` 的区别：探针是一次性验证代码，用完即弃；这里是**接下来会反复用**的工具。

## record_check.py — 录音体检

**为什么需要它**：`spike-asr` 的教训是，跑完 131 分钟的 ASR 才发现转出来是乱码，
而根因（SNR 14.4 dB、高频衰减 26-28 dB）其实在录音文件里就能直接测出来。

这个脚本把那个诊断固化下来 —— 录完当场跑，不行就重录，不用等 ASR 跑完。

### 用法

```powershell
py -3.11 -m pip install numpy
python record_check.py 录音.m4a
python record_check.py 录音1.m4a 录音2.m4a        # 批量
python record_check.py 录音.m4a --json           # 机器可读
```

需要 `ffmpeg` 在 PATH 里（用来读 m4a/mp3 等格式；标准 16k 单声道 wav 不需要）。

### 判定标准

| 指标 | 合格线 | 不合格意味着 |
|---|---|---|
| 信噪比 SNR | > 25 dB | 语音被噪声淹没，ASR 输出乱码 |
| 高频衰减 | > -15 dB | 辅音丢失，麦克风多半被遮挡 |
| 动态范围 | > 25 dB | 说话和静音音量差不多，录音链路把信号压平了 |
| 削波 | < 0.1% | 录爆了 |

### 实测参考

`class_16k.wav`（导致 spike-asr 失败的那段）跑出来的结果：

```
信噪比 SNR        14.4 dB   ← 不合格
高频衰减         -27.6 dB   ← 不合格
动态范围           9.9 dB   ← 不合格
削波            0.0000 %   ← 合格
```

四项里三项不合格，所以 ASR 输出不成句。**换任何模型都救不了。**

### 阈值是硬编码的，不是配置项

因为当前只有一批素材、一个场景。等积累了多种录音环境的数据，
再决定阈值要不要按场景分化 —— 现在拆成配置文件是过早抽象。

### 指标怎么算的

- **SNR**：逐帧 RMS 取 95 分位减 5 分位。不用「静音段 vs 语音段」是因为那需要 VAD，
  而 VAD 在低 SNR 下本身就不准 —— 这正是要检测的情况。分位数法不需要任何判定，反而更稳。
- **高频衰减**：2k-8k Hz 两个频段的平均能量，相对 400-2000 Hz（人声核心）。
- **动态范围**：逐帧 RMS 的 90 分位减 10 分位。
- **削波**：采样点绝对值 > 0.999 的比例。

频段定义（`BANDS`）与 `spike-asr/analyze_spectrum.py` 保持一致，方便对比历史数据。

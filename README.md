# 听刻

上课录音 → 老师提问时，快速给出答案。

## 为什么做这个

课上到中途老师突然提问，没跟上上下文的学生答不上来。
现有的手机实时转录（如澎湃 OS）只能把话转成字，转完还是得自己读懂、自己想答案。

「听刻」要做的是跨过这一步：**不只转写，而是理解上下文，直接给出可以照着说的回答。**
扩展方向：把课件、教材、参考资料一起喂进去，让回答有据可依。

## 当前状态：卡在 ASR 选型，不在录音

**这句话是 2026-10-03 改的。** 在那之前的结论是「卡在采集」——
现在有了五段真实课堂录音做对照，那个结论被推翻了。

### 关键实验：同一段音频，两个 ASR

从你的真实课堂录音里剪 90 秒，分别喂给本地模型和通义听悟：

| | 输出 | 专业术语命中 |
|---|---|---|
| 本地 sherpa-onnx int8 | 「跟知道离去中哥哥很远的那个跟…姐姐姐姐姐姐姐」 | **0 / 19** |
| 通义听悟（云端） | 「如果在右半平面发散，它就不稳定…根离虚轴越远越小」 | 6 / 19 |

**同一段音频，一个是不成句的音节堆砌，一个是能读懂大意的句子。**

对照实验还排除了两个解释：换 `modified_beam_search`、加 34 条领域热词，
**都没改善**。瓶颈在模型本身，不在解码配置。

完整数据和推理见 [`spike-asr/RESULTS_real_audio.md`](spike-asr/RESULTS_real_audio.md)。

### 所以「录音不合格」不等于「不能用」

五段录音**全部**被 `tools/record_check.py` 判为不合格，高频衰减集中在
−27 ~ −32 dB。但通义在其中几段上是**可用的**。

**决定成败的是两件事：录音质量 + ASR 模型鲁棒性。**
弱模型救不回来，不等于这段录音没用。

### 两个探针的结论（仍然有效）

- **`spike-asr/`**：本地 int8 模型在这类录音上**不可用**
- **`spike-enhance/`**：降噪 + 高频补偿**救不回信号**。
  辅音在录音时就丢了，放大 8 dB 放大的是同频段噪声。信号损失不可逆。

后者依然成立，且它说明「事后处理」这条路走不通——但不影响「换个更强的
ASR 模型就能用」这个判断。

## 一个重要的方法论教训

`spike-enhance` 暴露了：**指标合格 ≠ 录音可用。**

有一条录音被处理后指标刷到「SNR 29.4 / 高频 −20.7」，看着接近合格，
但 ASR 输出依然是乱码。

`tools/record_check.py` 是**筛查工具**（快速排除明显不合格的录音），
不是**验收工具**。最终判据永远是：**剪一段喂给 ASR，看转出来的字成不成句。**

2026-10-03 的实验又给这条加了一面：**指标不合格 ≠ 录音不可用。**
五段全判不合格，但通义能用。所以这个脚本是筛查工具，两个方向都不是判决书。

## 仓库说明

| 目录/文件 | 是什么 |
|---|---|
| `tools/` | **可复用工具**。`record_check.py` 录音体检、`batch_record_check.py` 批量体检、`compare_takes.py` 采集对照 |
| `COLLECTION.md` | 采集指南 + 已有素材的实测数据 |
| `spike-asr/` | ASR 探针（一次性，验完即弃）。含 [`RESULTS_real_audio.md`](spike-asr/RESULTS_real_audio.md) 真实素材对照实验 |
| `spike-enhance/` | 信号修复探针（一次性，验完即弃）。结论：救不回来 |

音频素材、模型权重、ASR 原始输出均不入库（见 `.gitignore`），
因为它们体积大且可能含课堂隐私内容。

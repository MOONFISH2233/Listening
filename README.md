# 听刻

上课录音 → 老师提问时，快速给出答案。

## 为什么做这个

课上到中途老师突然提问，没跟上上下文的学生答不上来。
现有的手机实时转录（如澎湃 OS）只能把话转成字，转完还是得自己读懂、自己想答案。

「听刻」要做的是跨过这一步：**不只转写，而是理解上下文，直接给出可以照着说的回答。**
扩展方向：把课件、教材、参考资料一起喂进去，让回答有据可依。

## 当前状态：卡在采集，两个探针已确认瓶颈

**一句话：录音质量不合格，算法救不回来。在拿到合格素材之前，后面全是空谈。**

### 探针一：`spike-asr/` — 端侧小模型能不能吃下课堂远场录音？

**结论：不能，但问题不在模型。**

素材本身的物理质量就不合格：

| 指标 | 实测 | 需要 |
|---|---|---|
| 信噪比 SNR | **14.4 dB** | > 25 dB |
| 2k-8k Hz 高频 | 比人声核心低 **26-28 dB** | 低 10-15 dB |
| 动态范围 | 9.9 dB | 30-40 dB |

131 分钟的课堂录音里，被判定为「有声」的只有 6.7%。ASR 输出是不成句的音节乱码。

### 探针二：`spike-enhance/` — 那降噪和高频补偿能救回来吗？

**结论：救不回来。**

三步处理（高通 → 谱减降噪 → 高频补偿 +8 dB）把体检指标从「四项全不合格」
刷到了「两项合格」：SNR 16.9 → 29.4 dB，高频衰减 −27.6 → −20.7 dB。

**但 ASR 输出依然是不成句的乱码。** 原因：辅音信息在**录音时**就丢了，
不是被压低了。放大 8 dB 放大的是同频段噪声。

**信号损失不可逆。录音时麦克风没收到的高频，算法变不出来。**

这也否定了 `spike-asr` 当时「优先做降噪」「高频补偿」的建议——
那两条是建议，现在被实测证伪了。

## 下一步：做采集对照实验

**唯一的关键路径是拿到合格录音。** 详见 [`COLLECTION.md`](COLLECTION.md)。

但第一件事不是照指南做，而是**先做对照实验**——因为指南里的建议全是推断，
没有实测数据支撑：

> 同一节课，用不同摆法录几段（兜里 / 桌上 / 桌上朝讲台 / 前三排桌上），
> 每段跑 `tools/record_check.py`，用数据确认哪条建议真的有用。

这样才能知道哪条建议可以省掉，也才知道「合格录音」到底要怎么才能录出来。

采集合格后，再决定 ASR 路线（端侧小模型 / 云端大模型）和交互形态。

## 一个重要的方法论教训

`spike-enhance` 暴露了：**指标合格 ≠ 录音可用。**

有一条录音被处理后指标刷到「SNR 29.4 / 高频 −20.7」，看着接近合格，
但 ASR 输出依然是乱码。

`tools/record_check.py` 是**筛查工具**（快速排除明显不合格的录音），
不是**验收工具**。最终判据永远是：**剪一段喂给 ASR，看转出来的字成不成句。**

## 仓库说明

| 目录/文件 | 是什么 |
|---|---|
| `tools/` | **可复用工具**。`record_check.py` 录音体检，录完当场跑，不合格就重录 |
| `COLLECTION.md` | 采集指南——当前唯一关键路径 |
| `spike-asr/` | ASR 探针（一次性，验完即弃）。结论：问题不在模型，在信号 |
| `spike-enhance/` | 信号修复探针（一次性，验完即弃）。结论：救不回来，重录是唯一出路 |
